## Limits and subsequent workflow correction

The observed runtime module count was 418 versus preflight stock's 419; the
specific difference was not diagnosed. ADB shell could read remoteproc names
but not state/firmware. `su -c` was inaccessible (rc=127), so root shell and
post-boot remoteproc health were not confirmed. The Manager's Working state
must not be substituted for that missing root-shell evidence.
No NoMount API/rule or SUSFS hiding behavior test, module installation or
long-duration stability assessment was performed.

The revised workflow verifies exact NoMount version/file records in
modules.builtin.modinfo extracted by ACK from linked vmlinux.o, plus its entry
in modules.builtin, instead of extracting a thin-archive member. KMI gates remain
strict. The operator also requested removing the dirty release suffix. New builds
use ACK's supported .scmversion override with the verified upstream commit suffix
and record the tracked source diff hash and integration input hashes separately.
The installed tested image retains its original dirty suffix; it is not patched
in place. A new artifact must pass its own gates before any further installation.
